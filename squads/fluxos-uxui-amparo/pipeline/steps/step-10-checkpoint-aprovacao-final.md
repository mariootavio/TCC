# Step 10: Checkpoint — Aprovação Final

Apresente ao usuário o veredito de revisão de Wagner WCAG
(`squads/fluxos-uxui-amparo/output/revisao-design.md`), juntamente com o
protótipo navegável de Pietro Prototipagem
(`squads/fluxos-uxui-amparo/output/prototipo-navegavel.md`) e as telas de
alta fidelidade de Telma Tela
(`squads/fluxos-uxui-amparo/output/telas-alta-fidelidade.md`), para
aprovação final deste ciclo de fluxos e UI/protótipo.

Pergunte explicitamente:

- Você concorda com o veredito de Wagner WCAG (APROVAR / REJEITAR / APROVAR
  COM RESSALVAS)?
- O protótipo navegável no Figma reflete fielmente os fluxos críticos
  desenhados por Joana Jornada, incluindo a saída rápida funcionando de
  qualquer ponto?
- Há alguma tela, fluxo ou pendência de design system (registrada por Telma
  ou Caio) que você quer ajustar manualmente antes de considerar este ciclo
  concluído?

Se o usuário aprovar, este ciclo é encerrado — o arquivo Figma (design
system, telas e protótipo navegável) e todos os relatórios ficam disponíveis
em `squads/fluxos-uxui-amparo/output/` para consulta em rodadas futuras ou
para alimentar a documentação do TCC (squad `tcc-documentacao`).

Se o usuário não aprovar, retorne ao Step 7 (Telma Tela) para ajustar as
telas, seguindo o mesmo fluxo de correção usado em caso de rejeição por
Wagner WCAG.

Este checkpoint é obrigatório antes de finalizar o ciclo — nenhuma rodada de
fluxos e UI/protótipo deve ser considerada concluída sem confirmação
explícita do usuário sobre o resultado final no Figma.
